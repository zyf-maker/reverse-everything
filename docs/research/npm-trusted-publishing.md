# npm Trusted Publishing: GitHub Actions

Verified against official npm and GitHub documentation on **October 18, 2026**.

## Findings

- npm Trusted Publishing uses GitHub Actions OIDC, so subsequent publishes do not need a long-lived `NPM_TOKEN`. The publishing job must grant `id-token: write`; GitHub documents that this permits requesting an OIDC token and does not itself grant write access to other resources. npm currently supports GitHub-hosted runners, not self-hosted runners. [npm Trusted Publishing](https://docs.npmjs.com/trusted-publishers/) · [GitHub OIDC](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-in-cloud-providers)
- Current minimum runtime is **Node.js 22.14.0 and npm CLI 11.5.1**. npm's example uses `actions/setup-node@v6`, sets `registry-url: https://registry.npmjs.org`, then installs, tests and publishes. The npm workflow file name must match the trusted-publisher configuration exactly; configure the filename only (including `.yml`/`.yaml`), and the file must live under `.github/workflows/`. The repository URL in `package.json` must exactly match the GitHub repository. [npm Trusted Publishing](https://docs.npmjs.com/trusted-publishers/)
- The trusted-publisher record is configured for a package and a specific GitHub owner, repository, workflow filename, and optionally a GitHub Environment name. If configured with an Environment, the publish job must use that same `environment` name. GitHub recommends adding environment protection rules when environments gate deployments. [npm Trusted Publishing](https://docs.npmjs.com/trusted-publishers/) · [GitHub OIDC](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-in-cloud-providers)
- **First package creation is separate from setting up OIDC trust.** npm's current guidance says to configure the first trusted publisher in the existing package's settings. Since the package does not yet exist, first create it with `npm stage publish` (available for new public scoped and unscoped packages since October 2, 2026); its first version is held for maintainer approval and is not installable until approved. Then configure the package's trusted publisher and use OIDC for later releases. [npm staged publishing](https://docs.npmjs.com/cli/v11/commands/npm-stage/) · [GitHub Changelog, October 2, 2026](https://github.blog/changelog/2026-10-02-npm-staged-publishing-now-supports-creating-new-packages/)
- Creating the first stage requires an npm account credential with package write access (an authenticated local npm session or a granular token); it cannot be bootstrapped by OIDC before the package exists. The first version remains staged until a maintainer promotes it. After package creation, configure the trusted publisher. [npm staged publishing](https://docs.npmjs.com/cli/v11/commands/npm-stage/) · [GitHub Changelog, October 2, 2026](https://github.blog/changelog/2026-10-02-npm-staged-publishing-now-supports-creating-new-packages/) · [`npm trust`](https://docs.npmjs.com/cli/v11/commands/npm-trust/)
- A trusted-publisher configuration must explicitly authorize the publish command used: `npm publish`, `npm stage publish`, or both. `npm trust github` requires at least one permission flag; use `--allow-stage-publish` for staged releases or `--allow-publish` for direct releases. [npm `npm trust`](https://docs.npmjs.com/cli/v11/commands/npm-trust/) · [npm staged publishing](https://docs.npmjs.com/cli/v11/commands/npm-stage/)
- For public packages published via OIDC from a public GitHub repository, npm automatically generates provenance; the workflow does not need `--provenance`. Provenance is unavailable when the source repository is private. [npm Trusted Publishing](https://docs.npmjs.com/trusted-publishers/)

## Repository-specific assessment

The current workflow is `replica-mcp-plugin/.github/workflows/publish-npm.yml`, but it uses Node 20 and the runner's default npm, which do not meet npm's Trusted Publishing minimums. It invokes direct `npm publish`; a newly created trust record will only permit that after explicitly enabling **Allow npm publish** (or the workflow should use the staged flow). The package manifest currently lacks `repository.url`, which npm requires to match the GitHub repository for trusted publishing. The npm package has not yet been created, so this workflow cannot publish it or establish OIDC trust as-is.

To use the lower-friction staged on-ramp: authenticate once as an npm account with package write permission, stage the first package version from the package directory, approve that stage on npm, then configure the GitHub trusted publisher and update the workflow to current Node/npm and the intended direct-publish or stage-only permission. This is a one-time registry ownership/setup action; later OIDC releases need no saved npm token.
